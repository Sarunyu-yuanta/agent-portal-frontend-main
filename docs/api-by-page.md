# API รายหน้า — Yuanta IC Portal

เอกสารนี้บอกว่า **แต่ละหน้า แต่ละส่วนบนหน้าจอ ต้องการข้อมูลอะไร** เพื่อให้ทีมหลังบ้านออกแบบ API ได้
ไล่จากโค้ดจริง (`page.tsx` ลงไปถึง component) ณ วันที่ 17 พ.ย. 2026

## อ่านเอกสารนี้อย่างไร

- **ข้อมูลที่ต้องการ / ตัวอย่างค่า / หน่วย** คือสิ่งที่ต้องตกลงกัน
- **อ้างอิงฝั่ง frontend** เป็นชื่อ type/field ที่ frontend ตั้งเอง backend **ไม่จำเป็นต้องใช้ชื่อนี้** — ฝั่ง frontend มี fetcher แปลงชื่อและ shape ให้ตรงกับหน้าจอได้
- **ระบบ (เสนอ)** เป็นการเดาว่าระบบไหนเป็นเจ้าของข้อมูล ต้องยืนยันกับทีมหลังบ้าน
- **อัปเดต** คือข้อมูลต้องสดแค่ไหน ดูหัวข้อ "ความถี่การอัปเดตข้อมูล"
- **"import ตรง"** = หน้านั้นยังอ่านไฟล์ mock ตรง ไม่ผ่าน hook ต้องสร้าง hook ก่อนต่อ API
- รายการ "ต้องมีวิธีดึง…" เขียนเป็นความต้องการ ไม่ใช่ชื่อ endpoint ให้ทีมหลังบ้านออกแบบเอง

## ความถี่การอัปเดตข้อมูล

| ระดับ             | ความหมาย                                                                         | ข้อมูล                                                                                                                                                                                                                         | หมายเหตุ                                                                                                                |
| ---------------- | -------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| **Push**         | Server ส่งมาเอง (WebSocket / SSE) หรือ webhook เข้า BFF แล้ว push ต่อ                 | สถานะคำสั่งซื้อ (หลังบ้านรับงาน, สำเร็จ, ถูกปฏิเสธ) · ลูกค้ากรอก Wealth Declare / Risk Consent ครบ · สถานะรายการซื้อขาย (จับคู่, จับคู่บางส่วน, ยกเลิก) · Risk alert ระดับวิกฤต (margin call, force sell) · Compliance alert · ราคาหุ้น ดัชนี order book | IC ต้องลงมือทันที หรือเป็นข้อมูลตลาด · ตอนนี้ 3 ตัวแรกจำลองด้วย timer ใน `orders-context.tsx` (15 / 10 / 12 วินาที) จุดนี้คือที่ต้องรับ push |
| **Poll 1–5 นาที** | Frontend ดึงซ้ำเป็นรอบ ด้วย option `pollMs` ของ `useEndpoint` (ค่า stale เริ่มต้น 5 นาที) | ยอดตะกร้า / โควตาคงเหลือ · สินค้าเปิด/ปิดจอง · ผลความพร้อมลูกค้าในฟอร์มจอง · กระดิ่ง (Note, ตลาด) · Reminders · Call log · ยอดนิยมสินค้า                                                                                                    | IC หลายคนจองสินค้าเดียวกัน ถ้ายอดเก่าอาจจองเกินโควตา · server ต้องตรวจโควตาซ้ำตอนจองเสมอ ไม่ว่าหน้าจอจะสดแค่ไหน                     |
| **รายวัน**        | ดึงตอนเปิดหน้า ข้อมูลเปลี่ยนวันละครั้งหรือตอนปิดตลาด                                         | AUM · holdings · เงินสด · หนี้สิน · allocation · วันหมดอายุ KYC · risk profile · NAV กองทุน · corporate actions · วันหยุด · House View · Research · NBA / AI insights                                                                 | ระบบต้นทางอัปเดตเป็นรอบ ควรแสดงเวลา "ข้อมูล ณ" ที่มาจากต้นทางจริง (ตอนนี้ hard-code หลายจุด)                                       |
| **เมื่อเปิดหน้า**    | ดึงครั้งเดียวตอนเปิดหน้า ไม่ต้อง poll                                                    | ข้อมูล IC · โปรไฟล์ลูกค้า · term sheet · เอกสาร · ข้อมูล issuer / บริษัท · หมวด Research · รายชื่อนักวิเคราะห์                                                                                                                             | ดึงครั้งเดียวต่อการเปิดหน้า cache ได้                                                                                          |
| **ตอนบันทึก**      | ได้ผลกลับทันทีตอนบันทึก ไม่ต้อง poll (sync ข้ามเครื่องตอนเปิดหน้า)                            | Notes / Reminders · ส่ง Proposal · หลักฐานการรับคำสั่ง · login · แชร์แคมเปญ · Pipeline                                                                                                                                             | ข้อมูลที่ IC สร้างเอง ผลกลับมาตอนบันทึก · reminder คำนวณเวลาเตือนที่หน้าจอเอง ไม่ต้อง push                                           |

- `useEndpoint` รับ `pollMs` ต่อ hook ได้แล้ว แต่ยังไม่มีช่องทางรับ push · ต้องตั้งความถี่ให้แต่ละ hook ตาม tier และเพิ่มช่องทาง push และช่องทาง push (WebSocket หรือ SSE) อย่างน้อยสำหรับคำสั่งซื้อและ risk alert
- **Alert ไม่ได้เร่งด่วนเท่ากัน**: margin call / force sell ต้อง push · KYC ใกล้หมดอายุอัปเดตรายวันพอ
- **Reminder ไม่ต้อง realtime**: เป็น Note ที่ IC ตั้งเอง หน้าจอรู้เวลาเตือนอยู่แล้ว
- ระดับในตารางเป็นร่างจากลักษณะข้อมูล ต้องยืนยันกับทีมธุรกิจและทีมหลังบ้าน

## เรื่องที่ใช้กับทุกหน้า

- **ค้นหา กรอง เรียง แบ่งหน้า ทำฝั่ง browser ทุกที่** (Orders, Research, KYC, กองทุน, หุ้นกู้ ฯลฯ) ถ้าข้อมูลจริงมีเยอะ ต้องให้ server รองรับ พร้อมจำนวนรวม
- **ข้อมูลต้องกรองตาม IC ที่ login ที่ server** ตอนนี้ frontend กรองเองโดยเทียบชื่อ IC ที่เป็นค่าคงที่
- **ส่งตัวเลขเป็นตัวเลข** ไม่ใช่ข้อความจัดรูป ("28.33%", "฿ 42M") และวันที่เป็น ISO ไม่ใช่ "14 Jul 2026" หรือปี พ.ศ.
- **ชื่อลูกค้า**: API อื่นส่งแค่ `clientId` ได้ frontend join ชื่อเองจากรายชื่อลูกค้า
- **สถานะที่ต้องรับจากระบบอื่น** (webhook หรือ poll): ลูกค้ากรอกเอกสารเสร็จ, หลังบ้านรับ/ตอบคำสั่งซื้อ, สถานะรายการซื้อขาย, สถานะ KYC
- **ค่าคงที่ที่ควรมาจาก backend**: อัตราแลกเปลี่ยน, ขั้นต่ำและโควตาสินค้า, notional ฝั่งไทย, กฎความเหมาะสมของ risk profile, เพดานภาษี
- **ข้อมูลที่ยังเป็นค่าสมมติ** (อย่าใช้เป็นแบบ): สัดส่วนพอร์ตต่อลูกค้า, บัญชีย่อย, หนี้สิน, รายการซื้อขาย, ข้อมูลหุ้นรายตัว, รายละเอียดกองทุน, ยอดขายสินค้า, KPI ในหน้า AI Insights / Compliance / Pipeline

ปฏิทินรายเดือน รวมวันเตือนจาก Note, corporate actions, event ของ desk และวันหยุดตลาด

| ส่วนบนหน้าจอ               | ข้อมูลที่ต้องการ                                                            | ตัวอย่างค่า                                     | หน่วย / รูปแบบ       | อ้างอิงฝั่ง frontend                                | ระบบ (เสนอ)       | อัปเดต |
| ------------------------ | ---------------------------------------------------------------------- | -------------------------------------------- | ------------------ | ----------------------------------------------- | ----------------- | ----- |
| ช่องวัน                    | วันหยุด (SET / ธนาคาร), corporate actions จัดกลุ่มตาม XD/XR/…, event, Note  | XD · PTT, SCB, KBANK · Chulalongkorn Day     | วันไทย              | `marketFeed()`, `holidaysByDay()`, `useNotes()` | Market data + CRM | รายวัน |
| Corporate action (popup) | ชื่อบริษัท วันที่ต่าง ๆ (X-Date, Record, Book Closing, Payment) ปันผลต่อหุ้น yield | PTT · 2.50 THB · 10/11/26                    | ข้อความจัดรูปจากต้นทาง | `CorporateActionFeedItem.record`                | Market data (SET) | รายวัน |
| Event (popup)            | ชื่องาน เวลา สถานที่ ข้อมูลเพิ่ม ลูกค้าที่เกี่ยวข้อง และเบอร์ติดต่อ                      | SET Outlook 2027 · 13:30–16:30 · Grand Hyatt | —                  | `MarketEventFeedItem`                           | Campaign / Desk   | รายวัน |

**ต้องมีวิธีดึง**

- Corporate actions รายเดือน พร้อมรายชื่อลูกค้าของ IC ที่ถือหุ้นนั้น
- Event ของ desk รายเดือน
- วันหยุดตลาด (ช่วง ±1 ปี)
- Note ที่มีวันเตือน

**การเขียนข้อมูล**

- สร้าง/แก้/ลบ reminder (เป็น Note)

**⚠️ ข้อควรรู้**

- รหัส XD/XR และหมวด event เป็นข้อความเปิด เพิ่มใหม่ได้โดยไม่ต้องแก้ frontend
- วันหยุดตามจันทรคติปี 2026/2027 เป็นค่าสมมติ

- ยังไม่มี hook
